Python 学习笔记：装饰器与上下文管理器

# Python# 装饰器# 上下文管理器# 学习笔记

一、装饰器：给函数”加 buff”

装饰器本质上是一个接收函数、返回函数的高阶函数。比如想在每个函数调用前后打印日志，不用修改每个函数，套一层装饰器就行。

1. 最基础的 log 装饰器

from functools import wraps

def log(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"调用开始 {func.__name__},{args},{kwargs}")
        result = func(*args, **kwargs)
        print(f"调用完成:{func.__name__},{result}")
        return result
    return wrapper

@log   # 等价于 add = log(add)
def add(a, b):
    return a + b

@log
def show_info(name, age, city="新乡"):
    return f"姓名:{name},年龄:{age},城市:{city}"

print(add(1, 2))
print(show_info("张三", 20, city="北京"))

运行结果：

调用开始 add,(1, 2),{}
调用完成:add,3
3
调用开始 show_info,('张三', 20),{'city': '北京'}
调用完成:show_info,姓名:张三,年龄:20,城市:北京
姓名:张三,年龄:20,城市:北京

@log 等价于 add = log(add)——把原函数传进去，返回包装后的新函数。

2. 两个易错点

写装饰器时最容易犯的错：

  • 忘记 return wrapper：包装函数必须返回出去，否则被装饰的函数会变成 None，一调用就报 TypeError: 'NoneType' object is not callable。
  • f-string 漏写 f：print({func.__name__}) 少了 f 前缀，打印出来的是一个集合 {'add'} 而不是函数名字符串。

3. 为什么要用 @wraps(func)

不加 @wraps 时，被装饰后的函数名会变成 wrapper：

print(add.__name__)   # 不加 wraps → 'wrapper'
print(add.__doc__)    # 不加 wraps → None（原文档字符串丢失）

加上 @wraps(func) 后，函数名、文档字符串等元信息都会保留，调试和生成文档时才不会混乱。

二、带参数的装饰器：三层嵌套

如果想让装饰器自己也能接收参数（比如”重复执行 n 次”），就需要三层函数嵌套：

from functools import wraps

def repeat(n):              # 第 1 层：接收装饰器参数
    def decorator(func):    # 第 2 层：接收被装饰的函数
        @wraps(func)
        def wrapper(*args, **kwargs):   # 第 3 层：真正执行的逻辑
            result = None
            for i in range(n):
                result = func(*args, **kwargs)
            return result   # 注意：return 要在循环外面！
        return wrapper
    return decorator

@repeat(3)
def say_hello(name):
    print(f"hello{name}")
    return f"hello{name}"

print(say_hello("张三"))

易错点：return result 一定要写在 for 循环外面。写在循环体里会导致第一次执行就退出，@repeat(3) 实际只执行 1 次。

记忆方式：@repeat(3) 等价于 say_hello = repeat(3)(say_hello)——先调用 repeat(3) 得到真正的装饰器，再用它包装函数。

三、实用案例：timer 计时装饰器

import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"{func.__name__} 执行时间: {end - start:.4f} 秒")
        return result
    return wrapper

@timer
def calc_sum(n):
    """计算1到n的和"""
    s = 0
    for i in range(n + 1):
        s += i
    return s

@timer
def sleep_demo(t):
    """休眠t秒"""
    time.sleep(t)
    return "休眠完成"

print(calc_sum(1000000))
print(sleep_demo(0.2))
print("函数名:", calc_sum.__name__)   # calc_sum（元信息保留）
print("文档字符串:", calc_sum.__doc__)  # 计算1到n的和

四、上下文管理器：自动管理资源

上下文管理器靠 __enter__ 和 __exit__ 两个魔法方法工作：

  • 进入 with 块时自动调用 __enter__（获取资源）
  • 离开 with 块时无论是否发生异常都会调用 __exit__（释放资源）

1. 手写文件管理器

class FileManager:
    def __init__(self, path, mode):
        self.path = path
        self.mode = mode

    def __enter__(self):
        self.file = open(self.path, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.file.close()
        return False   # 不处理异常，让它继续传播

with FileManager("data.txt", "w") as f:
    f.write("hello")
# 离开 with 块，__exit__ 自动关闭文件，不用手动 f.close()

__exit__ 的三个参数分别是异常类型、异常值、异常追踪信息；返回 False（或 None）表示不吞掉异常，异常会继续向外抛出。

2. 计时器上下文管理器

import time

class Timer:
    def __enter__(self):
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.end = time.time()
        print(f"耗时:{self.end - self.start:.4f} 秒")
        return False

with Timer():
    s = 0
    for i in range(1000000):
        s += i
    print("循环执行完毕", s)

五、小结

知识点关键写法易错点
基础装饰器def log(func): + 内层 wrapper忘记 return wrapper
保留元信息@wraps(func)不加则 __name__ 变成 wrapper
带参装饰器三层嵌套 repeat(n) → decorator → wrapperreturn 写在循环内导致只执行一次
上下文管理器实现 __enter__ / __exit____exit__ 返回 False 不吞异常

装饰器和上下文管理器都是 Python 里”把重复的样板代码抽出去”的利器：装饰器抽的是函数前后的通用逻辑（日志、计时、权限校验），上下文管理器抽的是资源的获取与释放（文件、锁、数据库连接）。
