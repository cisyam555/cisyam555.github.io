机器人如何自主探索未知环境？理解 SLAM、Nav2 与前沿探索

从陌生房间建图出发，理解 SLAM、Nav2 与 explore_lite 的分工，以及前沿检测、目标选择和实际导航约束。

# ROS 2# 自主探索# Nav2# SLAM# 机器人

把一台移动机器人放进陌生房间，要求它在没有人工遥控的情况下完成建图。它需要观察墙壁、绕开障碍，还要不断决定：接下来去哪里，才能看到更多尚未探索的空间？

如果目标已经确定，导航系统可以规划路径并控制机器人到达。但在自主探索任务中，目标本身也需要由程序产生。本文以 ROS 2 开源项目 m-explore-ros2 为例，解释探索决策如何与 SLAM、Nav2 配合，让机器人逐步扩大地图。

一、从“去厨房”到“探索整套房间”

先看一个熟悉的任务：让机器人从客厅走到厨房。

机器人需要确定自己的位置与朝向，知道厨房目标在哪里，再找到绕开沙发、穿过门口的路线。运动过程中，传感器继续提供新观测，定位与控制模块持续修正估计和动作。

这里，人已经给出了目的地。只要目标位姿明确，Nav2 就可以组织规划与控制。

如果换成“探索这套陌生房间”，情况就不同了。机器人最初只知道传感器覆盖范围内的一小片区域，厨房可能还没有出现在地图上。此时，系统需要根据不断变化的地图，自动选择能够扩大观测范围的位置。

自主探索增加的关键能力，就是持续生成探索目标。

二、SLAM、探索模块和 Nav2 怎样分工？

可以把这套系统理解为几个相互配合的模块。

模块 主要职责 交给其他模块的信息
SLAM 估计机器人位姿，建立和更新地图 地图与定位相关信息
explore_lite 根据地图寻找前沿，选择探索目标 下一处导航目标
Nav2 规划路径、计算运动指令并反馈导航结果 速度指令与任务状态
底盘和传感器 执行动作，测量运动与周围环境 新的里程计、激光等数据

SLAM 根据已有运动和观测估计“我在哪里、环境是什么样”，探索模块据此选择下一处目的地，Nav2 再组织机器人到达。真实移动带来新的观测，SLAM 继续扩展地图，探索模块也就有了新的选择依据。

这些模块持续协作，并不要求它们严格按同一频率依次执行。地图更新、探索目标计算和局部控制各有自己的运行节奏。

实际接入时，还要保证地图、机器人位姿和目标使用的坐标系能够通过 TF 正确关联。一个数值正确、参考坐标系却不匹配的目标，同样无法支持正常导航。

三、什么是前沿？

占据栅格地图把环境划分成许多小格。对入门理解而言，可以先关注三种状态：已知空闲、已知障碍和未知。

想象机器人已经扫描了走廊，但旁边房间内部还没有看清。走廊是已知空闲区域，房间深处是未知区域，两者在门口附近相接。

前沿（frontier）就是已知空闲区域与未知区域的交界。靠近这样的边界，传感器通常有机会获得新的环境观测。

“前沿”描述地图中的空间关系，与机器人当前面向哪里没有必然关系。它可能在机器人的侧面，也可能在刚刚经过的岔路口。

这里还要区分两个层次：从概念上看，前沿是一条边界；在 m-explore-ros2 的具体实现中，候选前沿格是“自身为未知，且上下左右至少有一个空闲邻格”的格子。因此，检测出的前沿格不等同于已经确认可安全停车的位置。

四、怎样从地图中找到下一处目标？

1. 从机器人附近搜索

项目的前沿搜索以机器人位置为参考，优先寻找空闲起点，再通过广度优先搜索（BFS）向周围扩展。

可以把 BFS 想成从当前位置一圈圈检查邻近格子。在这个过程中，程序寻找与空闲区域相邻的未知格，标记尚未处理的前沿候选。

从当前位置附近展开搜索，有助于把候选区域与机器人所在的连通区域联系起来。不过，这只是栅格层面的条件。狭窄通道是否容得下车身、目标是否满足导航约束，仍需要后续规划与控制检查。

2. 把零散格子组成前沿区域

一扇门附近通常会出现多个相邻前沿格。逐格比较既零散，也不利于描述整个边界。

项目通过八邻域关系聚合前沿格，也就是把横向、纵向和对角相邻的格子归为一组，再统计前沿大小、质心及距离等信息。过小的前沿还可以通过最小尺寸参数过滤。

前沿大小反映的是边界的规模，不等于后方未知房间的面积。门口很窄，后面也可能连接一个大房间。

3. 比较距离与前沿大小

有了多个候选区域，接下来需要排序。项目的评分主要结合距离项与前沿大小项：距离越近越有利，前沿越大也越有利，最终选择代价较小的候选。

参数 控制的倾向 增大后的通常影响
potential_scale 对距离的重视程度 更倾向选择较近的前沿
gain_scale 对前沿大小的重视程度 更倾向选择较大的前沿
min_frontier_size 允许参与选择的最小前沿尺寸 过滤更多碎小候选

例如，附近有一块较短的边界，远处有一块较长的边界。距离权重较高时，机器人更容易先处理附近区域；前沿大小权重较高时，较远的大前沿可能获得更高优先级。

这是一种基于当前地图的贪心选择。距离项使用前沿与机器人之间的几何距离信息，并不能直接代表绕过墙壁后的实际路径长度；前沿大小也只是潜在探索收益的近似指标。它没有计算访问所有前沿的全局最优顺序。

五、一次探索循环是怎样完成的？

继续使用“走廊旁边有一个未知房间”的例子。

  1. 获得当前地图和位姿。机器人扫描走廊，SLAM 更新已知空闲区域与墙体位置。
  2. 发现门口前沿。探索模块检测到门口附近的未知格与空闲区域相邻，形成候选前沿。
  3. 选择并下发目标。程序比较候选，选择目标位置，通过 Nav2 的 NavigateToPose 动作接口发送导航请求。
  4. 规划与执行。Nav2 根据代价地图规划路径，控制器持续生成运动指令，底盘执行。
  5. 重新观察与决策。机器人靠近门口后看见房间内部，地图中的部分未知区域转为已知，新的前沿出现在更深处，探索继续。

导航结果也是后续决策的依据。目标失败或长时间没有进展时，探索模块需要避免一直重复无效尝试。项目提供了黑名单等处理机制，但它们依赖相关状态与阈值，不能代替对失败原因的排查。

六、为什么有了前沿算法，机器人仍可能探索失败？

前沿存在，不代表目标一定可达

前沿区域的质心可能落在未知区域中，也可能位于不适合导航的位置。即使栅格上存在连接，机器人也可能因为车身宽度、障碍膨胀或转弯空间不足而无法通过。

排查时，需要同时观察前沿标记、导航目标、代价地图和规划结果。必要的改进包括在前沿附近重新选择安全目标点，或先检查候选目标是否存在可行路径。

目标过近，可能没有产生有效探索

导航通常允许一定的位置与朝向误差。如果探索目标离当前位姿太近，落在到达容差范围内，导航可能很快判定成功，但机器人并没有明显移动，也就没有获得足够的新观测。

若后续持续选到附近目标，就可能出现任务状态不断变化、地图却几乎不扩展的现象。设置最小目标距离、重新选择目标点，并联合检查导航容差，是可以考虑的改进方向。阈值应结合机器人尺寸、地图分辨率和传感器覆盖范围验证。

没有候选前沿，不一定意味着所有空间都已看清

碎小前沿可能被阈值过滤，一些区域可能暂时不可达，地图本身也可能存在缺口。判断探索效果时，应同时观察剩余未知区域、可通行范围和失败记录，而不能只看程序是否停止。

七、多机器人地图融合，还需要哪些协同能力？

m-explore-ros2 还包含多机器人地图融合能力。它可以利用已知初始位姿对齐地图，也支持估计相对变换的模式；实际融合效果取决于地图特征、重叠程度等条件。

把各机器人的地图拼接起来，解决的是环境表示的对齐问题。若希望多台机器人减少重复探索，还需要回答：哪些前沿已经由其他机器人负责？任务怎样分配？发生冲突后如何重新安排？

因此，在这个项目基础上实现更完整的协同探索，还需要补充前沿共享、任务分配和多机运动协调等模块。地图融合可以提供共同的环境参照，后续决策逻辑仍需单独设计。

八、从哪里开始验证自己的理解？

第一次实践可以先关注单机器人闭环：确认 SLAM 与 Nav2 正常运行，再接入探索节点，并在 RViz 中同时查看地图、机器人位置、前沿标记和导航目标。

之后固定环境，每次只调整一类参数，观察目标选择与行驶行为如何变化。例如，比较距离权重变化后，机器人是否更偏向就近探索；再检查最小前沿尺寸是否过滤了仍有价值的区域。

前沿探索把“下一步去哪”转化成了地图上的候选检测与排序问题。理解这条链路后，再分析导航失败、选点效率或多机任务分配，就能明确问题发生在哪一层，以及需要补充什么能力。
